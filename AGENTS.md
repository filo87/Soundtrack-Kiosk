# AGENTS.md

Repository guide for coding agents working on Soundtrack Kiosk.

## Read first

1. `.kilo/plans/1795620449114-baby-playlist-kiosk-plan.md` - the design source of truth: decisions, command contracts, guest flow, milestones, failure modes.
2. `README.md` - setup, scripts, data locations, operational behavior.
3. `docs/runbook.md` and `docs/printer-notes.md` - staff and hardware details.

If a user request conflicts with the plan, implement the user's request and update the relevant docs so the next agent sees the new behavior.

## Environment

- macOS only. The Tauri window uses macOS presentation options and simple fullscreen.
- pnpm 12 is the package manager. Do not introduce `package-lock.json` or npm/yarn commands.
- Rust is pinned by `rust-toolchain.toml` (`1.100.0`, rustfmt + clippy). Use rustup, not a Homebrew Rust.
- CUPS (`lp`, `lpstat`) is required for real printing; with no queue selected, development defaults to Mock.
- If `cargo` is not on PATH: `export PATH="$HOME/.cargo/bin:$PATH"`.

## Commands

| Command | Use |
|---|---|
| `pnpm install --frozen-lockfile` | Install dependencies. |
| `pnpm tauri dev` | Full app; a selected queue prints, no queue defaults to Mock. |
| `pnpm dev` | Vite only; Tauri IPC is unavailable. Do not use for flow work. |
| `pnpm test` / `pnpm test:watch` | Vitest. |
| `pnpm typecheck` / `pnpm lint` | TypeScript and ESLint. |
| `pnpm rust:test` / `pnpm rust:clippy` | Rust tests and lint. |
| `pnpm verify` | Required gate: typecheck, lint, Vitest, rustfmt check, clippy `-D warnings`, Rust tests. |
| `pnpm tauri build` | Release bundle; defaults to CUPS. |
| `pnpm tauri build --debug --bundles app` | Debug bundle; a selected queue prints, no queue defaults to Mock. |

Run `pnpm verify` before reporting completion. Do not claim hardware, Spotify-login, or launchd validation from automated tests.

## UI palette

Use the project palette consistently: Sweet Salmon `#FE938C`, Desert Sand `#E6B89C`, Wheat `#EAD2AC`, Cool Steel `#9CAFB7`, Cerulean `#4281A4`. The theme tokens live in `src/index.css`. Body text uses ink `#223843` and muted `#40535E` for contrast; do not introduce unrelated accent colors.

## Non-negotiable contracts

### Tauri commands and ACL

A new command must be added in all of these places:

1. `src-tauri/src/commands.rs` - implementation.
2. `src-tauri/build.rs` - `AppManifest::commands(&[...])`.
3. `src-tauri/src/lib.rs` - `generate_handler![...]`.
4. `src-tauri/capabilities/kiosk.json` - `allow-kebab-case-name`.
5. `src/lib/ipc.ts` - typed wrapper.
6. `src/lib/types.ts` - request/response DTOs if any.

`src/lib/acl.test.ts` asserts that the `build.rs` command list and capability `allow-*` list match. If it fails, fix both; do not weaken the test. The generated `src-tauri/permissions/autogenerated/*.toml` files are produced by the build and must not be hand-edited.

All admin commands must call `state.require_admin()?` first. Admin errors with code `ADMIN_LOCKED` close the overlay in the UI.

### DTO and serialization

- Tauri-facing Rust DTOs use `#[serde(rename_all = "camelCase")]`; TypeScript mirrors them by hand.
- Journal/file records use snake_case.
- `AppError` serializes to `{ code, message }`; the frontend wraps it in `KioskError`.
- `Health` changes require updating `src/lib/types.ts` and any UI that reads the new fields.
- When a DTO changes, update the mocks in `src/App.test.tsx`, `src/kiosk/machine.test.ts`, and any IPC tests.

### Guest flow and print layouts

- The choose screen has four options: `Orientation` (`portrait`/`landscape`) x `PrintLayout` (`cover`/`fit`).
- `PreviewPaths` has four paths: `portraitCover`, `portraitFit`, `landscapeCover`, `landscapeFit`.
- `commit_selection` requires both `orientation` and `layout`; the journal records `layout`.
- Cover crops with `resize_to_fill`; fit centers the full art on a white canvas of the target print size, leaving the margin where guests handwrite a memory or wish.
- Changing preview fields requires updates in `render.rs`, `PreviewPaths`, `useKiosk`, `ChooseScreen`, machine tests, and App mocks.
- Print filenames are `{id}-{orientation}-{layout}.png`; the Done screen uses the staged `prints/` file, not a Mock-output path.

### Duplicate policy

- A song is a duplicate by normalized title + artist (case/diacritics/remaster/live suffixes ignored) or by identical Spotify URI.
- Duplicates are still journaled and printed, but recorded as `playlist_skipped` and never sent to the outbox.
- The outbox also dedupes pending selections by song identity.
- Clearing local history resets this memory, so previously added songs can be added again afterwards. This is intentional; mention it in admin copy.

### Journals and config

- `journal.jsonl` is append-only and fsynced. Critical records (selection, print result) use `append_synced`/`append_many_synced`.
- Never rewrite or delete the journal directly. `Journal::clear` archives it and truncates in place; the in-memory cache is invalidated.
- New journal fields need `#[serde(default)]` behavior for legacy lines and defaults in `apply_line`.
- Update recent/CSV/admin projections when adding fields.
- Settings go through `AppState::update_config` (config lock + persistence + token client-id sync). Do not write `settings.json` directly.
- `set_config` preserves server-owned paper/ink counters; resets go through `mark_refilled` or `reset_printer_counters`.
- Admin PIN must be 4-12 digits and not `0000`. Fresh installs use `0000` only to get into admin once; the staff dot stays on until it is changed.

### Assets and security

- Asset protocol scope in `tauri.conf.json` must cover every directory shown via `convertFileSrc`: `previews/`, `prints/`, `mock-prints/`. Add new directories there.
- Tokens are stored in `tokens.json` with `0600`; `Secret` Debug output is redacted. Never log tokens or playlist contents.
- Use `log` macros, not `println!/eprintln!`, so output lands in the bounded LogDir.
- Do not add secrets, client ids, tokens, or event guest data to the repo.
- Avoid widening the asset scope or CSP without a concrete need.

### Printer backend

- A configured queue uses `Cups` even in a debug build; with no queue selected, debug builds use `PrinterBackend::Mock` and release builds use `Cups`.
- Override with `BABY_KIOSK_PRINTER=mock|cups` (the override wins over the configured queue).
- CUPS submission uses `lp`; status/waiting use `lpstat`; no-shell command execution.
- If no printer is configured, CUPS falls back to `lpstat -d`. Keep that behavior.
- `docs/printer-notes.md` holds provisional media/borderless options; update it when hardware is tested.

## Change recipes

### Add or change an admin action

1. Add the Rust command with `state.require_admin()?`.
2. Register it in `build.rs`, `lib.rs`, and the capability.
3. Add the typed wrapper in `ipc.ts`.
4. Add the control to the owning panel in `src/admin/sections/*` (or the shell for global actions),
   including a confirmation when destructive.
5. Add or update tests; run `pnpm verify`.
6. Update `docs/runbook.md` if staff behavior changes.

### Change the admin UI

1. `AdminOverlay.tsx` is the shell only: layout, nav, save bar, toasts, idle, close guard.
2. Feature panels live in `src/admin/sections/*`; shared controls live in `src/admin/ui.tsx`.
3. Pure validators live in `src/admin/validation.ts` and need table tests (accept and reject).
4. Keep the draft/baseline model and counter merging in `useAdmin.ts`; paper and ink counters are
   server-owned and must not make a form dirty.
5. Stay inside the project palette: Wheat page, Desert Sand surfaces/inputs, Cool Steel borders,
   Sweet Salmon for attention and primary actions, Cerulean for active/selected/focus. No red or
   amber. Do not put small text on Cerulean; use ink on `cerulean/15` with a Cerulean indicator.
6. Update `src/admin/AdminOverlay.test.tsx` (mockIPC) and `docs/runbook.md` for staff-facing
   changes. Run `pnpm verify`.

### Change the journal schema

1. Extend `JournalLine` with `#[serde(default, skip_serializing_if = "Option::is_none")]` where appropriate.
2. Add the field to `Selection`, initialize it in `apply_line`, and handle legacy defaults.
3. Update the constructor(s) and every call site.
4. Expose it in `RecentSelection`, CSV, and admin if useful.
5. Add projection/recovery tests, including a legacy line without the field.

### Change print rendering/layouts

1. Update `render.rs` preview generation and `PreviewPaths`.
2. Update `PrintLayout`/`Orientation` handling in `commands.rs`.
3. Update `types.ts`, `machine.ts`, `useKiosk.ts`, `ChooseScreen.tsx`, and `App.tsx`.
4. Update `App.test.tsx` and `machine.test.ts` fixtures.
5. Add render dimension/crop/fit tests; verify the asset scope still covers the output directory.

### Change settings/config

1. Add the field to `Config` with a serde default and a `Default` value.
2. Validate it in `set_config` (and in `config.rs` for reusable rules).
3. Add the admin control; preserve server-owned fields in `set_config`.
4. Update TypeScript `Config` and admin form.
5. Bump/migrate settings only if the shape is incompatible; `load_config` backs up unreadable files and starts from defaults.

## Testing expectations

- Pure logic: Rust unit tests or Vitest reducer tests.
- API behavior: wiremock in the Rust module that owns the client.
- UI flow: Testing Library + `@tauri-apps/api/mocks` (`mockIPC`, `mockConvertFileSrc`), with the full roster of preview paths.
- Command/capability drift: `src/lib/acl.test.ts` must stay green.
- Journal recovery: truncated tails, invalid UTF-8 lines, duplicate ids, clear/archive.
- Never assert hardware-specific behavior from the Mock backend. Document manual gates instead.

## Gotchas

- `pnpm dev` has no Tauri IPC; use `pnpm tauri dev`.
- `cargo` may not be on PATH; the rustup shim is `~/.cargo/bin`.
- Debug/Mock writes `mock-prints/`; the Done screen must use the staged `prints/` path so the asset scope allows it.
- The app data directory is `~/Library/Application Support/com.soundtrack.kiosk`; logs are in `~/Library/Logs/com.soundtrack.kiosk`.
- On startup, if the new data directory has no settings/tokens/journal, `paths::migrate_legacy_data` copies `com.soundtrack.babykiosk` into it once. The old directory is kept as a backup; do not delete it automatically.
- `settings.json` parse failures are backed up as `settings.json.corrupt-*`; the app starts with defaults and the default PIN, so staff must reconfigure and change the PIN.
- Clearing local history archives and empties the journal, drops pending playlist adds, and resets duplicate memory. The Spotify playlist and print files are untouched.
- `reset_printer_counters` zeroes both counters; `mark_refilled("paper"|"ink")` zeroes one.
- The LaunchAgent sample is `src-tauri/launchd/com.soundtrack.kiosk.plist`; the legacy label was `com.soundtrack.babykiosk`.
- The Spotify callback port `43821` is fixed; it is only bound during login. Changing it requires a code change and a matching Spotify redirect URI.
- Do not commit, amend, force-push, or change git config unless the user explicitly asks.
